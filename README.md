# 配置文件往返编辑（从 0 实现）

起始环境只有这份说明、`samples/**` 与 `.gitignore`，没有代码可抄。要新写入口脚本 `inikeep.py`（Python 3.13，
标准库，无依赖、无构建步骤）：按编辑脚本批量修改 INI 风格配置，改动之外的字节逐字节保留，并产出一份自包含的
HTML 报告。

## 一、范围

要做：按编辑脚本对配置做「改值、加键、删键」；除被替换、删除或插入的字节外，输出与输入逐字节相同；
一次运行处理多个脚本；把每份文件的编辑条数与字节保留率汇总成单文件 HTML 报告。

不做：不重排、不对齐、不做缩进或行尾归一、不清理注释、不补末尾换行；不解析成对象模型再整体重写；
不做类型转换、不合并重复键、不校验取值；不做节重命名、节删除、键排序、注释改写；不联网。

## 二、口径与公式

### 2.1 字节、行与空白

文件按字节处理；`\n` 是唯一行分隔符，每行含自己的 `\n`；`\r` 与制表符按普通内容字节原样保留；
最后一行可以没有 `\n`，末尾片段同样算一行。空白指空格与制表符。

### 2.2 逻辑行与行类型

- 逻辑行：物理行去掉行尾符后以奇数个连续 `\` 结尾时，下一条物理行属于同一逻辑行，可跨多行。
- 空行：去掉空白后为空。整行注释：第一个非空白字节是 `#` 或 `;`；连续且中间不夹其他行的整行注释构成注释块。
- 节头：去掉行尾注释、再去掉首尾空白后形如 `[名称]`，名称非空且不含 `]`、`#`、`;`。
- 键值行：落在某个节范围内、含 `=` 的行；`=` 之前去掉首尾空白后是键名（不得为空），行尾注释之前是值区。
- 原始行：其余所有行，包括第一个节头之前出现的键值行；原样保留、不参与编辑。

### 2.3 行尾注释与转义

行尾注释从「一个空白字节 + 未转义的 `#` 或 `;`」开始，那个空白属于注释；注释只在逻辑行的最后一条物理行上识别。
读到 `\\`、`\n`、`\t`、`\#`、`\;` 时分别表示 `\`、换行、制表、`#`、`;`，其它 `\x` 按两字节原样保留。
写回新值时一律规范转义：`\`→`\\`、换行→`\n`、制表→`\t`、`#`→`\#`、`;`→`\;`。

### 2.4 重复键与保留率

同一节内同名键可以出现多次，读取时全部保留；改值只作用最后一个出现，删除删掉全部出现。
节名与键名按原文字节比较、大小写敏感、不做转义。

字节保留率 =（输入字节数 − 所有 set 替换掉的字节数 − 所有 delete 删除掉的字节数）/ 输入字节数；
插入的字节不参与扣减；保留两位小数，输入为空时记 100.00%。

## 三、状态机与数据结构

解析按物理行推进：行首 → 判定空行 / 整行注释 / 节头 / 键值行 / 原始行 → 行尾是奇数个 `\` 时进入续行状态，
把后续物理行并入当前逻辑行；续行状态里不判定注释与节头。当前节随节头切换，节范围是节头之后到
下一个节头（或文件末尾）之前的全部行。文档模型形状自定，至少要有：物理行表（原始字节、逻辑行归属、类型）、
节表（节名 → 节头位置、节范围、节内最后一个非空白行）、键索引（(节名, 键名) → 出现位置，按出现顺序）。

编辑脚本是 UTF-8 JSON，字段只有两个：

    {"file": "01-inline-comments.ini",
     "edits": [{"op": "set", "section": "server", "key": "port", "value": "9090"},
               {"op": "delete", "section": "server", "key": "retries"}]}

`file` 相对 `--configs` 目录；`edits` 按数组顺序逐条应用，每条都基于前一条的结果重新定位。
`value` 是 JSON 字符串，先按 JSON 规则解码，再按 2.3 写回。

## 四、修改语义

set 改值（目标节内已有该键）：只替换值区字节，值区 = `=` 之后到行尾注释起点（无注释则是逻辑行末尾）之间的字节去掉
首尾空白后的部分，其余字节逐字节保留。原值区为空时，新值写到 `=` 后空白段的末尾；`=` 之后一个字节都没有时，
先补一个空格。原值用了续行时，值区包含中间的 `\` 与换行，改值后该逻辑行合并成一行。

set 加键（目标节内没有该键）：在目标节最后一个非空白行之后插入一行 `键名 = 值\n`（固定一个空格、固定 LF、无缩进）；
目标节不存在时，在文件末尾追加 `[节名]\n` 与该键行。插入位置不是行首（前一个字节不是 `\n`）时先补一个 `\n`，
保证新行独立成行。

delete 删键：删除目标节内该键的全部出现，每条连同它的续行与行尾符一起删除；注释块与空行原地保留，也不补空行。
键或节不存在时不改动，也不算错误。

往返与幂等：不做编辑时输出与输入逐字节相同；对结果再跑同一个脚本，结果逐字节不变。

## 五、输入输出与文件格式

    python inikeep.py [--configs 目录] --plan 脚本.json [--plan ...] [--out 目录] [--report 页面.html]

默认 `--configs samples/configs`、`--out var/out`、`--report var/report.html`，目录不存在时创建。
每个 `--plan` 独立处理一份配置，从 `--configs` 读原始字节，结果写到 `--out` 下的同名相对路径；
多个脚本指向同一文件时按命令行顺序覆盖。退出码 0 表示全部成功，参数或 IO 出错时非 0，且不留下半截文件。

报告是 `--report` 指定的单文件 HTML（UTF-8）：只用内联 `<style>` 与内联 `<svg>`，不引外链、不用 `<script>`、
不写绝对路径。每个脚本一节：文件名、编辑条数、新增 / 改值 / 删除三类计数（删除按实际删掉的键出现次数计）、
按 2.4 算的字节保留率，以及一张内联 SVG 水平条形图（每份配置一根条，长度与保留率成比例，标出文件名与百分比）；
数字不跑脚本也要能读。

## 六、性能与验收口径

预算（Python 3.13，冷启动计入）：单次运行的脚本数 ≤ 512、单文件 ≤ 16 MiB、合计输入 ≤ 64 MiB；
端到端 ≤ 10 s、峰值内存 ≤ 256 MiB；每个文件只读一次。

验收：

1. 逐个运行 `samples/edits/<名>.json`，`--out` 下的结果与 `samples/edits/<名>.expected.ini` 逐字节相同。
2. 对 `samples/configs/` 每份配置做零编辑往返，输出与输入逐字节相同（行尾、缩进、注释、重复键一律不许动）。
3. 对每个期望结果再跑一次同一脚本，结果逐字节不变。
4. 报告是能离线打开的单文件，结构与数字符合第五节，保留率与 2.4 的公式一致。
5. 验收会用未公开的同风格配置与脚本复核以上口径；不得读取 `samples/edits/*.expected.ini`，不得按文件名、
   长度或内容写死结果。

## 七、样例说明

`samples/edits/<名>.json` 与 `<名>.expected.ini` 成套，脚本里的 `file` 指向 `samples/configs/`：

| 样例 | 覆盖 |
| --- | --- |
| `01-inline-comments` | 行尾注释、续行、空值区，节内加键与删键 |
| `02-block-comments` | 注释块、删键后原位留什么、节头之前的遗留行不参与编辑 |
| `03-indent` | 缩进不一（含制表符）、空白行、节内追加、新建节 |
| `04-duplicates` | 重复键（改最后一个、删全部）、节头带行尾注释 |
| `05-escapes` | 带转义的值、末行没有换行符 |
| `06-comments-only` | 只含注释的文件，`edits` 为空数组，逐字节往返 |
| `07-new-section` | 在只含注释的文件上新建节与键，原注释逐字节保留 |

`07-new-section` 与 `06-comments-only` 共用同一份配置；`samples/notes.md` 是现场记录，不参与判定。
